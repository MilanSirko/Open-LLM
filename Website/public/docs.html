Quickstart

Open LLM exposes an OpenAI-compatible endpoint at https://openllm-api.com/v1. If you can call OpenAI, you can call Open LLM.

Authentication

Every request should include your API key in the apikey HTTP header. Generate one on the Get API Key page, where you can also configure provider-specific keys that optionally override the server's default provider access.

auth.py 
# Using the OpenAI-compatible client (library accepts an api_key)
from openai import OpenAI
client = OpenAI(base_url="https://open-llm-2fgm.onrender.com/v1", api_key="YOUR_API_KEY")

# Or, using plain requests: include your key in the `apikey` header
import requests
resp = requests.get("https://open-llm-2fgm.onrender.com/v1/serverinfo", headers={"apikey": "YOUR_API_KEY"})
print(resp.json())

Making a request

Send a chat completion just like you would with OpenAI. Set model to any slug from the Models page.

request.py 
response = client.chat.completions.create(
    model="model name",
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "Explain routing in one sentence."}
    ]
)

print(response.choices[0].message.content)

Request format

A chat completion accepts a model slug and an ordered array of messages. Optional fields like max_tokens let you cap the response length.

request_format.py 
response = client.chat.completions.create(
    model="model name",
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "Explain quantum computing simply."}
    ],
    max_tokens=500
)
  • model — the slug of the model to route to, or "auto".
  • messages — ordered chat turns with a role (system / user / assistant) and content.
  • max_tokens — optional cap on the number of tokens generated.

Response format

Responses match OpenAI's standard chat completion shape. The generated text lives at choices[0].message.content, and token accounting is returned under usage.

response.json 
{
  "id": "chatcmpl-abc123",
  "model": "groq...",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Quantum computing uses qubits that can be 0 and 1 at once..."
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 24,
    "completion_tokens": 118,
    "total_tokens": 142
  }
}

Available providers

The server currently supports the following providers: Groq, OpenRouter, Google, HuggingFace, Opencode (Zen), Cerebras, and NVIDIA. Browse the full model list on the Models page.

Note: You can add your own provider-specific key on the Get API Key page using the POST /keys/provider endpoint. When set, that provider's requests will use your key.

Smart auto-routing

Not sure which model to pick? Set model="auto" and a lightweight AI agent evaluates each request — its length, complexity and intent — then picks the most suitable available model automatically, optimising for latency, cost and capability. It's ideal when you don't want to hand-select a model per request, and it applies automatic fallback if the chosen provider is unavailable.

auto_route.py 
# Let Open LLM choose the best model for you
response = client.chat.completions.create(
    model="openllm/auto",
    messages=[{"role": "user", "content": "Summarise this contract."}]
)

# The chosen model is returned in the response metadata
print(response.model)  # e.g. "gemini-pro"

Rate limits

Requests are rate-limited per API key. The current default is 20 requests/minute. If you exceed it, the API responds with a 429 Too Many Requests error — back off briefly and retry. Need a higher limit? Reach out and we'll bump your key.

Error handling

Errors use standard HTTP status codes. The most common ones:

Code Meaning
400 Invalid model or malformed request body.
401 Invalid or missing API key.
429 Rate limit exceeded — slow down and retry.
500 Upstream provider error — usually transient.

Endpoints

This section summarizes the key endpoints, with exact request fields and examples using requests.

POST /v1/chat/completions

Main endpoint for chat completions. The request body expects the following JSON fields:

  • massage: the user prompt text (the current server API uses this exact field name).
  • model: the model slug or special values like openrouter/auto, openllm/auto, etc.
  • Optional: max_tokens (clients may send additional OpenAI style parameters in the server request).
requests_example.py 
import requests

url = "https://open-llm-2fgm.onrender.com/v1"
headers = {"Content-Type": "application/json", "apikey": "YOUR_API_KEY"}
body = {
    "massage": "Write a short introduction to artificial intelligence in English.",
    "model": "gemini-pro"
}

resp = requests.post(url, json=body, headers=headers)
print(resp.status_code)
print(resp.json())

Response: the server returns a structure similar to OpenAI. Generated text is in choices[0].message.content and token metadata appears under usage.

GET /models

Returns the list of supported model names and slugs. Simple GET request; no apikey required.

import requests
resp = requests.get("https://open-llm-2fgm.onrender.com/v1/models")
print(resp.json())

GET /model/{name}

Returns details for a single model: name, slug, provider, tier, kind. Replace {name} with the model slug or name.

import requests
resp = requests.get("https://open-llm-2fgm.onrender.com/v1model/gemini-pro")
print(resp.json())

GET /usage

Shows usage data for the user associated with the API key, in tokens. The apikey header is required.

import requests
headers = {"apikey": "YOUR_API_KEY"}
resp = requests.get("https://open-llm-2fgm.onrender.com/v1/usage", headers=headers)
print(resp.json())

GET /serverinfo

Returns general server info: status, version, uptime, model count, and available provider count.

import requests
resp = requests.get("https://open-llm-2fgm.onrender.com/v1/serverinfo")
print(resp.json())

GET /keys

Returns the user API keys and token statistics. Optional email query parameter can filter results. Returned keys are masked.

import requests
headers = {"apikey": "YOUR_API_KEY"}
resp = requests.get("https://open-llm-2fgm.onrender.com/v1/keys", headers=headers)
print(resp.json())

POST /keys/provider

Save your own provider specific key (for example HuggingFace or Groq). The body expects two fields: provider and provider_key. The apikey header is required.

import requests
url = "https://open-llm-2fgm.onrender.com/v1/keys/provider"
headers = {"Content-Type": "application/json", "apikey": "YOUR_API_KEY"}
body = {"provider": "huggingface", "provider_key": "hf_xxx..."}
resp = requests.post(url, json=body, headers=headers)
print(resp.json())

Retrieve provider keys with GET /keys/provider. Remove a provider key with DELETE /keys/provider/{provider}.

The exact behavior and field names for these endpoints are defined by the server implementation in server.py.
